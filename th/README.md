# การตรวจจับไฟป่าจากภาพถ่ายทางอากาศด้วยคอมพิวเตอร์วิทัศน์ (computer vision) และอากาศยานไร้คนขับ (drone)

> 🇹🇭 **ภาษาไทย** (เอกสารฉบับนี้) · [🇬🇧 English](../README.md)

ระบบตรวจจับไฟจากภาพถ่ายทางอากาศที่บันทึกด้วยอากาศยานไร้คนขับ โดยใช้โมเดล (แบบจำลอง)
[Ultralytics YOLO26](https://docs.ultralytics.com/models/yolo26/) ในการตรวจจับ
และใช้ไลบรารี [Supervision](https://supervision.roboflow.com/) ในการแสดงผลการตรวจจับ
ร่วมกับการติดตามวัตถุด้วยอัลกอริทึม ByteTrack

> **ปรับปรุงล่าสุดเมื่อเดือนสิงหาคม 2026** ผู้เขียนได้ปรับปรุงโค้ดชุดนี้ใหม่ทั้งหมด

> และผู้เขียนได้เพิ่ม [`main.ipynb`](main.ipynb) ซึ่งเป็นฉบับปรับปรุงของ
> [บทความบนบล็อกของ Roboflow](https://blog.roboflow.com/aerial-fire-detection/) ที่โครงการนี้จัดทำขึ้นประกอบ
> รายละเอียดปรากฏในหัวข้อ [การเปลี่ยนแปลงที่ผู้เขียนดำเนินการ](#การเปลี่ยนแปลงที่ผู้เขียนดำเนินการ)

## โน้ตบุ๊ก

**ควรเริ่มต้นที่ [`main.ipynb`](main.ipynb) ซึ่งเป็นฉบับปรับปรุงของบทความบนบล็อกของ Roboflow เรื่อง
[Aerial Fire Detection with Drone Imagery and Computer Vision](https://blog.roboflow.com/aerial-fire-detection/)**

เอกสารดังกล่าวครอบคลุมเนื้อหาชุดเดียวกับบทความต้นฉบับ ตั้งแต่เหตุผลที่ต้องตรวจจับไฟป่าจากมุมสูง
ภาพรวมการทำงานของระบบตั้งแต่ต้นจนจบ การเตรียมชุดข้อมูล การติดป้ายกำกับข้อมูล (labelling)
การฝึกโมเดล ไปจนถึงการนำโมเดลไปประยุกต์ใช้กับภาพนิ่งและวิดีโอ (inference)
โดยแตกต่างตรงที่ผู้เขียนปรับโค้ดให้ทำงานได้บนไลบรารีรุ่นปัจจุบัน
และแต่ละหัวข้อจะระบุไว้ชัดเจนว่าควรเปิดโน้ตบุ๊กส่วนใดขึ้นมาดำเนินการประกอบ

บทความต้นฉบับเผยแพร่เมื่อเดือนกันยายน 2023 โค้ดบางส่วนยังใช้งานได้ตามปกติ บางส่วนเพียงล้าสมัย
ส่วนหัวข้อการแสดงกรอบผลการตรวจจับ (annotation) และการติดตามวัตถุ (tracking) ไม่สามารถทำงานได้แล้ว
ทั้งนี้ `main.ipynb` ได้แจ้งเตือนไว้ ณ ตำแหน่งที่เนื้อหานั้นปรากฏ
แทนที่จะปล่อยให้ผู้อ่านพบปัญหาด้วยตนเองขณะดำเนินการ

## การเปลี่ยนแปลงที่ผู้เขียนดำเนินการ

### 1. โน้ตบุ๊กไม่สามารถแสดงผลได้

สาเหตุมีสองประการ ซึ่งแยกจากกัน

- โน้ตบุ๊ก inference บนวิดีโอ (เดิมชื่อ `Supervision_Video_Inferencing.ipynb`) มีบล็อก `metadata.widgets`
  ที่รายการ `application/vnd.jupyter.widget-state+json` ขาดคีย์ `state`
  ซึ่งเป็นเงื่อนไขที่ทำให้ GitHub แสดงข้อความ *"Invalid Notebook"*
- โน้ตบุ๊กสำหรับการฝึกโมเดลมีขนาด 1.68 MB ซึ่งเกินเพดานการแสดงผลของ GitHub ที่ประมาณ 1 MB
  โดย 1.67 MB ในจำนวนดังกล่าวเป็นภาพผลลัพธ์ที่ฝังมาในรูปแบบ base64

เดิมโน้ตบุ๊กทั้งสามไฟล์อยู่ในรูปแบบ `nbformat 4.0` ซึ่งไม่มี cell ID ปัจจุบันผู้เขียนปรับเป็น 4.5
กำหนด cell ID ครบถ้วน ล้าง output ที่ฝังอยู่ออกทั้งหมด และจัดระเบียบ metadata ใหม่
ขนาดไฟล์จึงลดลงจากระดับ MB เหลือระดับ KB (ฉบับภาษาอังกฤษที่รากของคลังโค้ดมีขนาดประมาณ
8 KB, 5 KB และ 10 KB ส่วนฉบับภาษาไทยซึ่งรวมเป็นไฟล์เดียวมีขนาดประมาณ 32 KB
ซึ่งใหญ่กว่าเนื่องจากข้อความภาษาไทยจัดเก็บเป็น UTF-8 หลายไบต์ต่อหนึ่งอักขระ)

นอกจากนี้ ผู้เขียนได้กำหนดให้ [nbstripout](https://github.com/kynan/nbstripout) ทำหน้าที่เป็น
clean filter ของ Git (ดู `.gitattributes`) output และ execution count จึงไม่ถูกบันทึกไปกับ commit
ซึ่งมีความสำคัญกับส่วนที่ 3 เป็นพิเศษ เนื่องจากเซลล์แสดงวิดีโอฝังไฟล์ผลลัพธ์มาในรูปแบบ base64

### 2. โค้ดมิได้เพียงล้าสมัย แต่ไม่สามารถทำงานได้

- เปลี่ยนจาก `yolov8m.pt` มาใช้ **YOLO26** ซึ่งเป็นสถาปัตยกรรมแบบครบวงจร (end-to-end)
  และไม่ต้องผ่านขั้นตอน NMS
- โค้ดเดิมตรึงเวอร์ชันไว้ที่ `ultralytics==8.0.20` (มกราคม 2023) ซึ่งไม่สามารถติดตั้งบน Colab
  ปัจจุบันได้ ส่วน `supervision==0.1.0` เรียกใช้ module path (`supervision.tools.detections`,
  `supervision.draw.color`) ที่ไม่มีอยู่แล้ว
- อาร์กิวเมนต์ `BoxAnnotator(..., labels=...)` ถูกถอดออกตั้งแต่ supervision 0.22
  ปัจจุบันการแสดงผลแยกเป็น `BoxAnnotator` และ `LabelAnnotator`
- **การติดตามวัตถุเป็นส่วนที่ได้รับผลกระทบมากที่สุด** โน้ตบุ๊กเดิมโคลนคลังโค้ด
  [ByteTrack](https://github.com/ifzhang/ByteTrack) มาคอมไพล์ YOLOX จากซอร์ส
  ติดตั้ง `onemetric` และ `cython_bbox` และยังต้องใช้ `sed` แก้ไขอีกสองบรรทัด
  เพื่อหลีกเลี่ยงข้อบกพร่องซึ่งต้นทางได้แก้ไขไปนานแล้ว ชุดเครื่องมือดังกล่าวไม่สามารถคอมไพล์ได้อีกต่อไป
  ปัจจุบัน ByteTrack รวมอยู่ใน Ultralytics แล้ว คำสั่ง
  `model.track(persist=True, tracker="bytetrack.yaml")` เพียงบรรทัดเดียวจึงทดแทนขั้นตอนทั้งหมดได้
  ข้อสังเกตประการหนึ่งคือ ลูปการเรนเดอร์ของโค้ดเดิมสร้างออบเจกต์ `BYTETracker` ขึ้นมาแต่ไม่เคยเรียกใช้
  สิ่งที่เรียกว่า "การติดตามวัตถุ" ในผลลัพธ์เดิมจึงเป็นเพียงผลการตรวจจับรายเฟรมที่ไม่มีการติดตามใด ๆ
- ByteTrack ได้รับผลการตรวจจับที่มีค่าความเชื่อมั่นต่ำโดยเจตนา
  เนื่องจากการนำกรอบที่มีค่าความเชื่อมั่นต่ำกลับมาจับคู่กับ track ที่ยังดำเนินอยู่
  คือที่มาของความแม่นยำโดยส่วนใหญ่ ผู้เขียนจึงกรองค่าความเชื่อมั่น *ภายหลัง* ขั้นตอน tracking
  แทนที่จะตัดข้อมูลออกตั้งแต่ต้นทาง
- ยกเลิกการระบุพาธ `runs/detect/train` แบบตายตัว โดยเปลี่ยนไปอ่านค่าจาก `results.save_dir` แทน
  เนื่องจาก Ultralytics จะเพิ่มลำดับเป็น `train2` และ `train3` ในการเรียกใช้ครั้งต่อ ๆ ไป
- API key ของ Roboflow อ่านค่าจาก Colab Secrets หรือตัวแปรสภาพแวดล้อม
  แทนการระบุ `api_key="YOUR_API_KEY"` ไว้ในเซลล์โดยตรง
- เพิ่มขั้นตอนการแปลงวิดีโอเป็น H.264 ด้วย ffmpeg เนื่องจาก Supervision บันทึกไฟล์ด้วยตัวเข้ารหัส `mp4v`
  ซึ่งเบราว์เซอร์ไม่สามารถถอดรหัสได้ วิดีโอผลลัพธ์จึงไม่สามารถแสดงผลในโน้ตบุ๊กได้

เนื่องจากล้าง output ออกทั้งหมด โน้ตบุ๊กจึงไม่แสดงกราฟผลการฝึกบนหน้า GitHub อีกต่อไป
ซึ่งเป็นข้อแลกเปลี่ยนที่หลีกเลี่ยงไม่ได้สำหรับไฟล์ที่มีขนาดเกินเพดาน
อีกทั้งผลลัพธ์ชุดเดิมย่อมล้าสมัยเมื่อเทียบกับโค้ดที่ปรับปรุงใหม่อยู่แล้ว
